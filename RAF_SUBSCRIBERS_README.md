# Система подписки на RAF-ивенты

## Описание

Реализована система регистрации пользователей на рассылку о новых RAF-ивентах. Когда кто-то создает и запускает RAF-ивент, все подписчики получают уведомление в личные сообщения с ботом.

## Возможности

### Для пользователей

1. **Команда `/reg`** - подписка/отписка от рассылки
   - Работает только в личных сообщениях с ботом
   - При первом использовании подписывает на рассылку
   - При повторном использовании показывает кнопку для отписки

2. **Уведомления о новых RAF-ивентах**
   - Автоматически приходят при запуске нового ивента
   - Содержат:
     - Название ивента
     - Название чата, где проходит ивент
     - Время начала и окончания
     - Список призов с их редкостью и шансом
     - Кнопку с прямой ссылкой на сообщение в чате (если доступно)
     - Кнопку со ссылкой на чат (если ссылка на сообщение недоступна)

### Для создателей ивентов

- Никаких дополнительных действий не требуется
- При активации RAF-ивента уведомления отправляются автоматически
- Ссылка на сообщение о начале ивента сохраняется в БД и используется в уведомлениях

## Технические детали

### Изменения в базе данных

Добавлена таблица `raf_event_subscribers`:
```sql
CREATE TABLE IF NOT EXISTS raf_event_subscribers (
    user_id BIGINT PRIMARY KEY,
    username TEXT,
    subscribed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
)
```

Добавлено поле в таблицу `raf_events`:
```sql
ALTER TABLE raf_events ADD COLUMN announce_message_link TEXT
```

Это поле хранит ссылку на сообщение, которое бот публикует в чате о начале RAF-ивента (не путать с `source_message_link`, которое вводит создатель ивента).

### Новые методы в database.py

1. `subscribe_to_raf_events(user_id, username)` - подписать пользователя
2. `unsubscribe_from_raf_events(user_id)` - отписать пользователя
3. `is_subscribed_to_raf_events(user_id)` - проверить подписку
4. `get_all_raf_subscribers()` - получить всех подписчиков
5. `update_raf_event_message_link(event_id, message_link)` - сохранить ссылку на сообщение
6. `get_raf_event_with_chat_info(event_id)` - получить ивент с информацией о чате

### Новые методы в bot.py

1. `reg_command()` - обработчик команды `/reg`
2. `handle_unreg_raf()` - обработчик кнопки отписки
3. `_notify_raf_subscribers()` - отправка уведомлений подписчикам

### Логика работы

1. **Подписка:**
   - Пользователь пишет `/reg` боту в личку
   - Бот сохраняет user_id и username в таблицу подписчиков
   - Выводит подтверждение с информацией о том, что будет приходить

2. **Отписка:**
   - Если пользователь уже подписан, показывается кнопка "Отписаться"
   - При нажатии удаляется из таблицы подписчиков

3. **Уведомления:**
   - При активации RAF-ивента (нажатие кнопки "Начать"):
     - Сообщение публикуется в целевом чате
     - Формируется ссылка на это сообщение (публичные и приватные чаты)
     - Ссылка сохраняется в `raf_events.source_message_link`
     - Получается список всех подписчиков
     - Каждому отправляется уведомление с информацией об ивенте
     - Уведомление содержит кнопку для перехода к ивенту

## Формат ссылок

- **Публичные чаты** (с username): `https://t.me/{username}/{message_id}`
- **Приватные чаты** (супергруппы): `https://t.me/c/{chat_id_без_-100}/{message_id}`
- **Fallback**: Если ссылка на сообщение не создана, используется `chat_link` из `chat_configs`

## Примеры использования

### Подписка на рассылку
```
Пользователь -> Боту в личку: /reg
Бот: ✅ Вы успешно подписались на рассылку о RAF-ивентах!
```

### Отписка от рассылки
```
Пользователь -> Боту в личку: /reg
Бот: ✅ Вы уже подписаны... [Кнопка: Отписаться]
Пользователь -> Нажимает кнопку
Бот: ✅ Вы успешно отписались от рассылки
```

### Уведомление о новом ивенте
```

⏱ Время: 02.08.2026 14:30 - 03.08.2026 14:30

• 1000 монет (legendary, 5%)
```

## Безопасность и производительность

- Команда `/reg` работает только в личных сообщениях
- Между отправками уведомлений добавлена задержка 0.05 секунды
- Ошибки отправки уведомлений логируются, но не прерывают процесс
- Статистика отправки уведомлений записывается в лог

## Миграция существующих данных

Таблица создается автоматически при запуске бота через `init_db()`. Никаких дополнительных миграций не требуется.
