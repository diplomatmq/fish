## Структура базы данных

### Новая таблица `raf_event_subscribers`
```sql
CREATE TABLE IF NOT EXISTS raf_event_subscribers (
    user_id BIGINT PRIMARY KEY,
    username TEXT,
    subscribed_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
)
```

### Новая колонка в `raf_events`
```sql
ALTER TABLE raf_events ADD COLUMN announce_message_link TEXT
```

Поле `announce_message_link` хранит прямую ссылку на сообщение, которое бот публикует в чате о начале RAF-ивента.

## Как работает система

### 1. Подписка
```
Пользователь -> /reg в личке
Бот -> Сохраняет в raf_event_subscribers
Бот -> Отправляет подтверждение
```

### 2. Создание RAF-ивента
```
Создатель -> /raf в личке
Создатель -> Вводит данные (название, чат, призы)
Создатель -> Оплачивает создание
Создатель -> Нажимает "Начать"
```

### 3. Активация и рассылка
```
Бот -> Публикует сообщение о начале в целевом чате
Бот -> Формирует ссылку на это сообщение
Бот -> Сохраняет ссылку в announce_message_link
Бот -> Получает всех подписчиков из БД
Бот -> Для каждого подписчика:
    - Формирует уведомление с информацией об ивенте
    - Добавляет кнопку со ссылкой на сообщение
    - Отправляет в личку
Бот -> Логирует статистику отправки
```

## Формат ссылок

### Публичные чаты
```
https://t.me/{username}/{message_id}
```

### Приватные чаты (супергруппы)
```
https://t.me/c/{chat_id_без_-100}/{message_id}
```

Пример:
- Chat ID: `-1001234567890`
- Message ID: `456`
- Ссылка: `https://t.me/c/1234567890/456`

## Известные ограничения

1. Уведомления не приходят, если пользователь заблокировал бота
2. Ссылки на сообщения в приватных чатах работают только для участников чата
3. Если бот не админ в чате, он не может получить название через API
